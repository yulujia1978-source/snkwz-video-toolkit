## 1.0.15 开发者署名

软件主界面底部加入“Developed by SNKWZ”。

## 1.0.14 放宽监听与保存目录限制

同一任务只要求监听目录与保存路径不是同一个实际目录，上下级目录、其他任务用过的目录均可选择。符号链接指向同一目录仍视为相同。旧版记录的输出目录不再导致整片目录被拦截。

循环防护改为按实际已保存的成品文件跳过，不再屏蔽整个输出目录。已有任务、移除任务和重做归档中的成品路径会在载入时恢复；重开后仍跳过这些文件，目录中的其他原视频继续扫描。此规则按原保存路径识别，手动移动或复制到新路径的视频会作为新来源。

## 1.0.13 退出确认与窗口恢复

修复点击关闭后选择继续处理无法返回主窗口：确认退出前保留主窗口，退出提示改为窗口内确认，继续处理后显示原窗口。点击Dock图标也会恢复窗口，后台任务不重启。

## 1.0.12 自动建立同名输出文件夹

保存时只需选择一个路径，系统自动在里面建立同名子文件夹。单独处理按源视频名建立，例如“成品/视频A/视频A.mp4”；自动合并按监听文件夹名建立，完整合并及分集成品都放在该文件夹内。手动合并按填写的输出名称建文件夹，未填写时使用首个视频名。手动与自动处理均生效。

已有同名文件夹会复用，同名成品仍自动增加编号，旧成品保留。若同名路径是文件或符号链接，会提示保存失败，可换路径重试。历史已保存成品不移动，完成记录仍保留；新保存的成品使用此规则。

## 1.0.11 人声分离进度显示

修复合并视频进入人声分离后总进度一直停在94%的显示问题。现在手动处理和自动任务卡片显示当前阶段、已生成人声的分段数、正在处理的段号及阶段用时；音频准备、人声整理和音轨合成也分别显示进度。分离阶段的百分比按已生成分段计算，单段处理期间可能保持不变，用时继续更新；全部分段确认生成且分离进程成功退出后才显示本阶段100%。

本版不改变分离模型或音质参数，也不加快模型推理。已取消的任务需要重新开始；安装新版后生效。

## 1.0.10 来源命名与完成后自动停止

任务卡片使用监听文件夹的原名称。逐个处理时，成品保留源视频文件名；完整合并输出“来源文件夹名.mp4”，约50分钟分集输出“来源文件夹名-第001集.mp4”等。自动任务不再使用上方手动区域的“输出名称”，不同来源各自命名；旧成品不会被改名，重名仍自动编号。

每组默认勾选“完成后自动停止”。当前来源中等待稳定、排队、编码和保存全部结束后停止该组，保留卡片和完成记录，其他组继续处理。已停止后新增视频需再点开始；已有成功版本会跳过。需要长期接收新视频时，停止后取消此勾选再开始即可。

状态明确显示“处理完成，已自动停止”；存在失败时显示“处理结束，有失败视频，已自动停止”。保存失败仍保留可恢复成品并提示错误。空目录等待一个稳定窗口后停止，零字节的复制占位文件继续等待，正在保存时不会提前停止。

退出前重新读取引擎状态：所有任务结束且不再监听时直接退出；仅监听时明确说明没有视频正在处理；确有处理或保存时才提示会中断当前任务。

## 1.0.9 自动任务支持合并与压缩

修复自动任务强制关闭合并的问题。现在启动时采用上方实际勾选的完整合并、约50分钟分集合并、视频压缩及其他效果；卡片显示本次模式、压缩开关和编码方式，便于核对。已有任务采用启动时参数，修改上方选项后需停止并重新启动。

合并模式会等当前观察到的文件全部稳定后，按文件名数字顺序将未处理的视频合成一批。零字节的复制占位文件会继续等待；过场视频要求至少两个主视频。后续新增的视频作为下一批，不追加到已保存成品。每组独立合并，多个任务依然轮流排队。输出名称采用上方“输出名称”；不同任务需要不同名称时，分别修改名称并启动。

任务8等旧任务的完成记录会继续跳过原文件。要改成合并并重新处理全部来源：先停止并等当前处理保存完，点击该卡片“重做全部（保留原成品）”，再勾选合并/压缩并开始。此操作归档原处理记录，不删除原片或旧成品，重名成品自动编号。

## 1.0.8 卡片启动引导与错误提示

目录没选齐时，卡片按钮显示“选择文件夹并开始”，点击后依次选择缺少的监听和输出目录，保存配置后直接启动。已有配置仍显示“开始此任务”。全部启动会逐组检查，缺少目录的任务会明确标红提示，不影响其他完整任务启动。目录选择、参数或引擎报错会同时显示在任务卡片和自动任务区顶部，并滚动到提示位置；取消目录选择也会说明任务尚未启动。

## 1.0.7 多任务启动修复

自动任务启动会忽略手动模式的合并、完整合并及过场选项，继续采用其他画面和输出参数，不修改手动模式的勾选。选择文件夹结束后立即恢复添加和启动按钮。每组配好两个文件夹后，使用“开始此任务”或“全部启动”；上方“开始手动处理”用于导入的视频。

# 视频去重 Mac 版

基于 `Playground/video-dedupe.html` 与其视频处理引擎制作的独立 macOS 桌面应用，当前交付 Apple Silicon（M1/M2/M3/M4 等）版本，最低 macOS 13.5。

## 1.0.6 多组文件夹任务

现在“一组监听文件夹 + 一组输出文件夹”就是一个任务。默认显示「任务 1」，选择好两个文件夹后自动保存；点击「＋ 添加任务」继续增加任务 2、任务 3。完整配置会在刷新和重开后保留，没有设置固定任务组数上限。

每组分别提供开始、停止、失败重新入队、打开输出文件夹和移除操作；也可以全部启动、全部停止。启动时采用上方处理参数，所以既可以全部使用相同参数，也可以先启动一组、改参数后再启动另一组。运行中的任务固定使用其启动时参数。

多组同时监听，视频统一串行并轮流调度，每组只把成品保存到自己的输出文件夹。停止一组不影响其他组；有当前视频时会先完成保存。移除需要先停止并等当前视频完成，移除不会删除原视频和已保存成品。

1.0.14起改为只排除有保存记录的成品文件，目录上下级关系不再限制。原 1.0.5 的单组配置和完成记录会自动迁移成任务 1。目录列表保存在 `auto-queues.json`，各组完成记录保存在 `watch-groups/<任务编号>/auto-queue.json`，旧单组记录保留备份。

## 1.0.5 自动连续处理

在「自动连续处理」区域选择监听文件夹和输出文件夹，设置好上方画面处理参数，再点击「开始自动处理」。已有视频和以后新增的视频都会递归扫描、按自然文件名顺序逐个处理并自动保存。每次启动固定一套参数，改参数需停止后再启动；自动模式逐个处理，不使用合并或过场。

- 默认文件连续 10 秒大小和修改时间未变后入队，可设 3–600 秒。处理期间若源文件又变化，会清理这次临时结果，等待新版本稳定后重新入队。网络传输或大文件复制暂停较久时，可适当延长稳定时间。
- 输出目录可放在监听目录内或其上级，只跳过有保存记录的成品文件；二者不能相同。不跟随符号链接，也会排除辅助视频与隐藏文件。
- 完成记录按路径、大小、修改时间保存，刷新和重开后不重复处理同一版本。需要用新参数重做已成功视频时，可使用普通手动批处理。
- 单个视频失败会跳过并继续。停止后完成当前视频并保存，不再启动下一个；未开始的视频下次启动继续。
- 保存失败会停止接收，未保存成品仍保留。修复或重新选择输出目录后点击开始，会优先重试保存，避免重复编码。过期成品需将失败视频重新入队处理。
- 失败或上次中断的视频可点击「失败视频重新入队」，再开始；退出应用停止监听并取消进行中的编码，重开后需手动点击开始。画中画辅助视频重开后需重新选择。

自动模式只在本机应用打开期间运行。目录、参数和处理记录保存在应用数据目录的 `auto-queue.json`，最近 100 条记录显示在界面。导入的源视频不删除、不移动；输出仍采用重名自动编号和保存校验。

## 1.0.4 刷新按钮

右上角新增「↻ 刷新」，支持 ⌘R。空闲时重新加载界面，保留设置、通过原生选择器导入的视频及辅助视频、当前结果和输出文件夹。处理中只刷新进度；导入和保存期间保留当前操作。浏览器拖入的视频暂采用刷新列表以保留文件对象。

## 1.0.3 黑线显示修复

旧版黑线位于最外侧 2px，开启黑色边框时会与边框重叠。新版在裁剪、边框、缩放完成后绘制单条横线；默认垂直位置 90%、粗细 8px、不透明度 100%，均可调。0% 为顶部、50% 为中间、100% 为底部。粗细按最终输出像素计算。勾选「黑线技术」后对新任务生效，旧成品需要重新处理。

## 1.0.2 速度优化

升级首次启动自动启用 Apple 硬件加速、兼容时保留原音轨，并将软件编码预设改为 veryfast；之后手动修改的选项会保留。直接读取本地文件，画面无需改变且输出编码兼容时跳过视频重编码。处理状态显示 FFmpeg 实时倍速。

硬件编码的成品大小与软件编码可能不同；有画面特效时仍需要逐帧处理。

## 使用

打开 `dist/视频去重.app`，或打开 DMG 后将应用拖到「应用程序」。选择视频或整个文件夹，勾选处理功能，点击「开始处理」并选择输出文件夹。文件夹会递归导入视频，按自然文件名顺序排列；可在列表中调整顺序。

1.0.1 已移除掐头去尾和始终镜像，并清除旧设置中的对应选项。

保留原版的分集合并、完整合并、过场、网格、裁剪、调色、锐化、边框、黑线、画中画、H.264/H.265 压缩、暂停、继续、取消和日志。这里的「去重」指这些视频处理操作，不是查找并删除重复文件。

应用内置 Node.js、FFmpeg、FFprobe，主界面使用原生窗口和 WebKit，不需要原网站、8080 服务或后台登录。视频不上传到外部服务。原生文件选择直接读取本地源文件，导入时不再预复制；浏览器拖入的文件仍通过本机临时副本处理。原文件不修改，处理完成前请保留原文件的位置。输出遇到同名文件会自动增加编号。保存完成、文件大小验证通过后才清理内部成品副本。

未保存成品保留 24 小时；应用关闭期间暂停清理，下次启动检查过期时间。退出会取消进行中的任务；未保存的成品可在下次启动时重新选择文件夹保存。中断的编码需要重新提交。

人声分离使用可选的本机 Demucs；默认检测 `~/Library/Python/3.9/bin/demucs`，也可通过 `DEMUCS_BIN` 环境变量指定。Demucs 与模型不包含在安装包中，首次使用模型可能需要联网下载。回归测试使用模拟分离器验证顺序、分段及合成；本机还通过了真实 Demucs 模型推理和成品音轨测试（合成测试音频，未对真实讲话素材进行听感评价）。

## 构建

```sh
./scripts/build.sh
```

构建需要 Xcode Command Line Tools。默认从原 `Playground` 项目的依赖提取 FFmpeg 和 FFprobe，从当前 PATH 提取 Node.js；可通过 `NODE_BIN`、`FFMPEG_BIN`、`FFPROBE_BIN` 或 `VIDEO_DEDUPE_ORIGINAL` 指定替代位置。当前构建脚本针对 arm64。

```sh
node --test tests/engine-original.test.js tests/desktop.test.cjs tests/features.test.cjs tests/black-line.test.cjs tests/auto-queue.test.cjs tests/auto-queue-manager.test.cjs tests/auto-queue-desktop.test.cjs
VD_TEST_DEMUCS=1 node --test --test-name-pattern="installed Demucs" tests/features.test.cjs
VD_SELF_TEST_REPORT=/tmp/video-dedupe-smoke.json dist/视频去重.app/Contents/MacOS/VideoDedupe
cat /tmp/video-dedupe-smoke.json
```

测试覆盖原引擎 18 项回归，以及桌面服务鉴权、本地导入、真实编码、输出时长、音轨、重名保护和源文件校验。应用自检验证 WebKit 页面、脚本加载及桌面适配器。原生选择框的人工点击流程未自动验证。

本地数据和诊断日志位于 `~/Library/Application Support/VideoDedupeMac/`；选项存储在应用偏好设置。内部 HTTP 服务仅绑定随机的 `127.0.0.1` 端口，每次启动生成独立令牌，校验 Host 与 Origin。

应用采用本机临时签名，未使用 Apple Developer ID 公证。当前交付用于本机运行；当前复用的 FFmpeg 构建包含 nonfree 组件，其 `-L` 输出明确标注不可再分发；此包仅供本机使用。公开发行前需替换为可再分发的构建，并完成正式签名和公证。

## 文件

- `Sources/App.swift`：原生窗口、文件选择、引擎生命周期、设置保存。
- `Resources/video-dedupe.html`：已适配的页面（内嵌桌面适配脚本）。
- `Resources/desktop.js`：桌面适配脚本源文件，修改时同步页面内嵌内容。
- `Resources/server.cjs`：独立本地服务、本地导入与安全保存。
- `Resources/services/video-dedupe/index.js`：已做速度优化的原处理引擎。
- `Resources/auto-queue.cjs`：连续扫描、稳定检测、串行队列、完成记录与自动保存。
- `Resources/auto-queue-manager.cjs`：多组任务管理、持久化、轮流调度和全局输出目录排除。
- `Resources/auto-queue-ui.js`：多任务列表、各组目录选择与状态更新。
- `tests/`：引擎回归、桌面集成与自动队列测试。
